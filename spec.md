# Спецификация проекта: Онлайн-деканат МУКПиД

## 1. Концепция и Ролевая модель (RBAC)
«Онлайн-деканат МУКПиД» — это единое цифровое пространство для организации учебного процесса, спроектированное по принципу **Mobile-First**. 

Система поддерживает две основные роли с жестким разделением прав доступа:
*   **🎓 Студент (`student`):** Имеет доступ строго к своим персональным данным (успеваемость, заявки, индивидуальные уведомления, обращения) и к общему расписанию своей учебной группы.
*   **👨‍🏫 Преподаватель (`teacher`):** Видит свое личное расписание занятий. Имеет доступ к электронным ведомостям только тех групп, в которых он ведет дисциплины. Обрабатывает входящие обращения от студентов.

**Безопасность (Изоляция данных):** Доступ к конечным точкам API защищен JWT-токенами. Попытка запросить ресурсы чужого `user_id` (IDOR-уязвимость) блокируется на уровне middleware (возвращается статус 403 Forbidden).

## 2. Схема базы данных (Ключевые сущности)

*   **`users` (Пользователи):** `id` (UUID), `email`, `password_hash`, `role` (student/teacher), `full_name`, `faculty`, `group_id`.
*   **`lessons` (Расписание):** `id` (UUID), `group_id`, `subject_id`, `teacher_id`, `room`, `type` (Лекция/Семинар/Практика), `starts_at`, `ends_at`, `change_type` (move/cancel), `change_note`.
*   **`grades` (Успеваемость):** `id` (UUID), `student_id`, `subject_id`, `score` (0-100), `semester`.
*   **`requests` (Заявки студентов):** `id` (UUID), `student_id`, `type` (Справка/Отпуск и т.д.), `goal`, `comment`, `delivery` (pdf/offline), `step` (0:Принята -> 3:Выдана).
*   **`inquiries` (Обращения):** `id` (UUID), `student_id`, `teacher_id`, `subject`, `text`, `reply_text`, `status` (new/work/done).
*   **`notifications` (Уведомления):** `id` (UUID), `user_id`, `kind` (deadline/news/change/request), `title`, `text`, `is_read`, `created_at`.

## 3. REST API Endpoints

### Auth & User
*   `POST /api/auth/login` — Авторизация (возвращает JWT).
*   `GET /api/auth/me` — Получение данных текущего профиля по токену.
*   `PATCH /api/user/prefs` — Обновление настроек уведомлений.

### Schedule & Grades
*   `GET /api/schedule` — Расписание для текущего пользователя (по группе или ID преподавателя).
*   `GET /api/grades` — Получение успеваемости студента.
*   `GET /api/gradebook/groups` — Список групп преподавателя для заполнения ведомости.
*   `PUT /api/gradebook/:subject_id/:group_id` — Массовое сохранение баллов преподавателем.

### Requests & Inquiries
*   `GET /api/requests` — Список заявок студента.
*   `POST /api/requests` — Создание новой заявки.
*   `PATCH /api/requests/:id/cancel` — Отмена заявки.
*   `GET /api/inquiries` — Входящие обращения (для преподавателя) или исходящие (для студента).
*   `POST /api/inquiries` — Создание обращения студентом.
*   `PATCH /api/inquiries/:id` — Ответ преподавателя на обращение и смена статуса.

### Notifications
*   `GET /api/notifications` — Лента уведомлений.
*   `PATCH /api/notifications/:id/read` — Отметка о прочтении.

## 4. Пользовательские сценарии (User Flows)

1.  **Подача заявки (Студент):** Переход в раздел «Заявки» $\rightarrow$ Выбор типа документа $\rightarrow$ Заполнение полей «Цель» и «Способ получения» $\rightarrow$ Система создает запись со статусом `Принята` и присылает уведомление.
2.  **Выставление оценок (Преподаватель):** Раздел «Ведомость» $\rightarrow$ Выбор дисциплины и группы $\rightarrow$ Ввод баллов (0-100) напротив ФИО студентов $\rightarrow$ Нажатие «Сохранить» $\rightarrow$ Обновление таблицы `grades`.
3.  **Обратная связь (Обращения):** Студент задает вопрос по курсовой через форму $\rightarrow$ Преподаватель видит бейдж с количеством новых вопросов $\rightarrow$ Открывает диалог, переводит статус в `В работе` и пишет ответ $\rightarrow$ Студент получает Push-уведомление.

## 5. ИИ-интеграции и "Фишки" (Масштаб нейротехнологий)

*   **ИИ-предиктор успеваемости:** На основе текущих баллов (`grades`) нейросеть формирует подсказки для студента (например: "Средний балл 68. Самый низкий результат: История России. Обратите внимание перед сессией").
*   **Умные уведомления (Smart Alerts):** ИИ автоматически генерирует персонализированные пуши на основе изменений в `lessons` (например, "Пара перенесена") и дедлайнов.
*   **Генерация PDF "на лету":** При статусе заявки `Готова`, бэкенд формирует официальный бланк справки в формате PDF, автоматически подставляя ФИО студента и факсимиле.
