# Реализованный API

Источник требований — [spec.md](../spec.md). Контракты ниже описывают код ветки интеграции. Реальное прохождение всех сценариев PostgreSQL следует подтверждать интеграционными тестами, отдельно от сборки и проверок без БД.

## Общие правила

Ответы JSON: `{data: ...}`, ошибки: `{error: {code, message}}`. 400 — ввод, 401 — нет действующей сессии, 403 — нет доступа/CSRF, 404 — отсутствующий либо недоступный объект, 409 — конфликт состояния/версии, 413 — размер файла, 429 — частота входа. PDF и материалы возвращаются бинарным ответом, DELETE/выход/«прочитать все» — 204.

JWT HS256 находится только в HttpOnly-cookie; сервер проверяет подпись, обязательные claims, срок и активную запись sessions. Срок — 8 часов без продления. Роль и пользователь определяются из БД, а не параметров клиента. Выход отзывает сессию. Cookie `session` локально, `__Host-session` + Secure в production, SameSite=Lax, Path=/, ответы no-store. Подпись использует JWT_SECRET из окружения (минимум 32 байта).

Все POST/PUT/PATCH/DELETE требуют `X-CSRF-Protection: 1`. При JSON нужен Content-Type: application/json. Origin должен совпадать с APP_ORIGIN; cross-site запрещён, CORS не включён. Клиент и API используют один origin через proxy /api. Лимит входа — 10 попыток в минуту с IP.

## Заявки и документы

Студент:

- GET `/api/requests` — собственные заявки, новые первыми.
- POST `/api/requests` — `{type,purpose,comment?,delivery}` → 201. type: study/order/leave/retake, purpose 1–500, comment до 2000 после trim, delivery pdf/office. Создание заявки и уведомления атомарно.
- PATCH `/api/requests/:id/cancel` — submitted/in_progress → cancelled. Повторная отмена допустима. Чужой объект 403; отменённые записи остаются в истории.
- GET `/api/requests/:id/pdf` — сохранённый PDF владельцу, только delivery=pdf, ready/issued.

Сотрудник:

- GET `/api/staff/requests` — все заявки с ФИО, факультетом, программой, курсом и группой; без содержимого документа и снимка черновика.
- PATCH `/api/staff/requests/:id/status` — `{status,reason?,draftId?}`. submitted → in_progress; in_progress → ready; ready → issued. Для типов кроме study разрешено submitted → ready. submitted/in_progress → rejected требует reason (1–1000 после trim). Повтор статуса идемпотентен; обратные переходы запрещены.
- POST `/api/staff/requests/:id/prepare` — `{verified:true}`, только study в in_progress. Проверяет полноту ФИО/факультета/программы/курса/группы/цели, сохраняет снимок `study-v2`, ID проверившего, время, новый draftId. Сбрасывает отметку предпросмотра.
- POST `/api/staff/requests/:id/preview` — `{draftId}` → PDF «ЧЕРНОВИК», фиксирует предоставление этого черновика сотруднику. Факт человеческого прочтения сервер установить не может: интерфейс явно требует открыть и проверить файл.
- Готовность study требует актуальный draftId, проверку и предоставленный предпросмотр. При изменении учебных сведений нужен новый черновик. Статус, неизменяемый финальный PDF, данные сотрудника и уведомление сохраняются транзакционно; отмена и выпуск используют блокировку строки. При сверке снимка учебные сведения блокируются на чтение до конца транзакции.
- GET `/api/staff/requests/:id/pdf` — сохранённый PDF ready/issued, включая office. Скачивание не меняет статус.

В JSON записи: id, studentId, type, purpose, comment, delivery, status, createdAt, updatedAt, processedBy, readyAt, rejectionReason и служебные отметки проверки/draftId/previewedAt. `documentBase64` и `draftSnapshot` не возвращаются. Чужому студенту и преподавателю черновик недоступен. После выпуска повторное скачивание выдаёт те же байты. Реальные подписи и юридически значимые документы не реализованы.

## Уведомления и настройки

Любая авторизованная роль читает только свои уведомления:

- GET `/api/notifications`: id, studentId (историческое имя поля получателя), kind, title, body, readAt, createdAt.
- PATCH `/api/notifications/:id/read` → обновлённая запись; чужой/отсутствующий ID → 404.
- PATCH `/api/notifications/read-all` → 204, только текущий получатель.
- GET `/api/user/prefs` → `{deadlines:true,schedule:true,news:false}` либо сохранённые значения.
- PATCH `/api/user/prefs` → непустое подмножество этих булевых полей.

Заявки, ответы и оценки создают служебные уведомления независимо от настроек. schedule=false отключает новые уведомления об изменениях расписания. Для deadlines/news в этом этапе есть хранение настроек, но нет генератора событий. Клиент обновляет ленту при фокусе и раз в минуту. Почта и Web Push не подключены.

## Расписание

GET `/api/schedule?from=&to=` — только группа текущего студента или teacher_id текущего преподавателя. Время ISO 8601 с поясом, период не более 62 дней. Ответ — массив занятий: id, groupId, groupName, subject, kind, teacherId, teacherName, room, startsAt, endsAt, changeNote, cancelled.

Только staff:

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/staff/groups?q= | Поиск названия/факультета/программы, до 30 групп |
| GET | /api/staff/teachers | ID и ФИО преподавателей для выбора |
| GET | /api/staff/groups/:id/lessons?from=&to= | `{group,lessons}` за период |
| POST | /api/staff/groups/:id/lessons | Создание занятия → 201 |
| PATCH | /api/staff/lessons/:id | Частичное изменение занятия |
| DELETE | /api/staff/lessons/:id | Отмена с сохранением записи → 204; повтор допустим |

Создание: `{subject,kind,teacherId,room,startsAt,endsAt,changeNote?}`. kind lecture/seminar/practice. teacherName берётся из записи выбранного пользователя; одного имени для назначения недостаточно. Длительность положительная и не больше 12 часов. Пустые строки запрещены. Отменённое занятие нельзя редактировать. Пересечения группы, ID преподавателя и нормализованного названия аудитории запрещены. Все изменения расписания сериализуются транзакционной advisory-блокировкой, уведомления записываются в той же транзакции.

МСК применяется в интерфейсе, CSV и описании времени; в БД — timestamptz. Старые занятия без teacher_id не показываются произвольному преподавателю. CSV и повторы пока выполняются последовательными запросами с отчётом о частичном успехе; серии определяются по совпадающим атрибутам, отдельного series_id нет. CSV требует точное уникальное полное ФИО существующего преподавателя. Полноценные серии/атомарный импорт остаются открытым вопросом.

## Ведомости и успеваемость

`teaching_assignments` связывает преподавателя, предмет, группу, семестр, форму контроля, срок и версию. Назначения заполняются seed или отдельной административной операцией вне интерфейса. Демо-seed добавляет «Макроэкономику» существующему демопреподавателю для двух демогрупп.

- GET `/api/gradebook/groups` — только свои ведомости преподавателя: id, teacherId, subjectId, groupId, subject, group, teacher, semester, form, deadline, version, students `[{id,name,score}]`.
- PUT `/api/gradebook/:id` — `{version,scores:[{studentId,score}]}`, до 500 записей. score целое 0–100 или null. Проверяется назначение преподавателя, членство каждого студента в группе, дубликаты, срок и версия. Ошибка любой строки откатывает весь запрос. Сохранение повышает версию; параллельная/устаревшая запись получает 409. Изменившимся студентам создаются уведомления.
- GET `/api/grades` — только собственные назначения/баллы студента: `[{id,name,form,semester,score}]`. Не выставленный балл — null.

`grade_entries` используется для новых баллов. Прежняя таблица grades с текстовым result сохранена без потери данных; автоматическое преобразование старых результатов не выполняется.

## Обращения

- GET `/api/inquiries/teachers` — назначения преподавателей группы текущего студента.
- POST `/api/inquiries` — только студент; `{assignmentId,subject,text}`; тема 1–200, текст 1–5000. Преподаватель определяется назначением.
- GET `/api/inquiries` — студент видит свои, преподаватель — адресованные ему; staff получает 403. Запись содержит исходный текст, статус, сведения студента, даты и replies `[{id,inquiryId,authorId,text,createdAt}]`.
- PATCH `/api/inquiries/:id` — адресованный преподаватель меняет status на progress/closed. Начальный статус new.
- POST `/api/inquiries/:id/replies` — `{text}` → 201, только адресованный преподаватель. У закрытого обращения ответ запрещён (409), сначала открыть. Ответы сохраняются историей; уведомление студента и запись ответа атомарны.

Студенческая страница позволяет отправлять новые обращения и читать историю; продолжение студентом существующего диалога пока не реализовано.

## Учебные материалы

- GET `/api/materials/assignments` — назначения своей группы студента или свои назначения преподавателя.
- GET `/api/materials` — материалы этих назначений, без содержимого: id, assignmentId, title, fileName, mimeType, size, createdAt, subject, group.
- POST `/api/materials` — только преподаватель своего назначения: `{assignmentId,title,fileName,contentBase64}` → 201 `{id}`.
- GET `/api/materials/:id/file` — бинарное скачивание с повторной проверкой назначения/группы, attachment, nosniff.
- DELETE `/api/materials/:id` — только преподаватель своего назначения → 204.

До 5 МиБ на файл, PDF/TXT/PNG/JPG, проверка сигнатуры или UTF-8, строгий base64 и безопасное имя. Файлы хранятся в БД как base64 для прототипа; антивирус, квоты общего объёма и объектное хранилище не реализованы.

## Миграции и проверки

0006 добавляет kind расписания; 0007 добавляет назначения, баллы, обращения/ответы, материалы, настройки, teacher_id и отмену занятий, поля черновика справки и kind уведомлений. Существующие таблицы/заявки не удаляются. После обновления: `npm run db:migrate`, затем `npm run db:seed`.

`npm run test:unit` не требует БД: проверяет 26 новых маршрутов без сессии/с поддельной сессией и CSRF, файлы до предельного размера, ввод, схему дат, генерацию PDF и время расписания. `npm run test:integration` требует отдельный TEST_DATABASE_URL с применёнными миграциями. Проверяются авторизация, два студента/преподавателя, чужие объекты, атомарность ведомости, конфликты версий/расписания, черновики, отказ и гонка отмены/выпуска. Наличие теста не означает успешное выполнение в текущем окружении.
