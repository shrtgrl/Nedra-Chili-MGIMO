# Цифровой деканат — конкурсный прототип

Колясик — бэкенд; Аслан — интерфейс; Кирилл — продукт и отчёт.

## Локальный запуск

Нужны Node.js LTS, npm и запущенный Docker с Compose. Один раз подготовьте окружение и установите зависимости:

```sh
cp .env.example .env
npm ci
cd apps/web && npm ci && cd ../..
```

В `.env` задайте `JWT_SECRET` (не менее 32 байт) и четыре `SEED_*_PASSWORD` (не менее 12 символов каждый). Значения остаются только в локальном окружении. Для последующих запусков из корня проекта достаточно:

```sh
npm run dev:all
```

Команда ждёт готовности PostgreSQL, применяет миграции, добавляет отсутствующие демоаккаунты и запускает API с веб-клиентом. Повторный seed не меняет пароли существующих аккаунтов. `Ctrl+C` останавливает API, веб-клиент и контейнер базы; данные базы остаются в Docker volume. Если API и веб-клиент уже остановлены, базу можно отдельно остановить командой `npm run dev:stop`.

Интерфейс: http://localhost:5173. API: http://127.0.0.1:3001/health.

Проверка типов: `npm run check`. Сборка: `npm run build`. Запуск сборки: `npm start`.
Сервер /health запускается без базы. Схема из восьми таблиц описана в apps/api/src/schema.ts, SQL-миграции — в apps/api/drizzle.
Значения .env.example предназначены только для локальной разработки. При изменении реквизитов обновите также DATABASE_URL.

## Интерфейс

При необходимости API и веб-клиент можно запустить отдельно: `npm run dev` из корня проекта и `npm run dev` из `apps/web`. Общий запуск — `npm run dev:all`.

Откройте `http://localhost:5173`. Vite передаёт `/api` на локальный API. Для входа используйте email демонстрационного пользователя и соответствующий пароль из серверного окружения. Вход, профиль и выход работают с API и серверной сессией. Расписание, оценки, заявки, уведомления и ведомости пока показывают локальные демоданные браузера; для них API ещё не подключён.

Новые демоадреса: `student@edu.mukpid.ru`, `student2@edu.mukpid.ru`, `teacher@mukpid.ru`, `staff@staff.mukpid.ru`. После обновления API выполните `npm run db:migrate` и `npm run db:seed`. Подсказки адресов в форме входа обновлены; выбор роли и перенаправление обновляются фронтендом отдельно.

## Docker и публикация

Сейчас `compose.yaml` запускает только PostgreSQL в контейнере. Данные базы сохраняются в Docker volume `postgres_data`; API и Vite работают на компьютере через Node.js. Docker позволяет всем разработчикам поднять одинаковую версию базы, но сам по себе не публикует приложение в интернете.

Для разработки и показа на одном компьютере аренда сервера не нужна. Чтобы сайт был постоянно доступен другим людям по адресу в интернете, потребуется размещение веб-клиента, API и PostgreSQL у хостинг-провайдера либо на собственном сервере, а также HTTPS и настройка маршрута `/api`. Для краткой демонстрации можно использовать временный туннель, но публичный деплой в этом проекте пока не настроен.

## Следующий этап

Согласовать docs/api.md с Асланом и поля данных с Кириллом. Схема и два студента уже созданы локально. Вход, выход и GET /api/auth/me реализованы. Далее — API расписания, оценок, заявок и уведомлений.
Авторизация и профиль подключены к интерфейсу. Остальные бизнес-маршруты и публичный деплой пока не реализованы.

## Таблицы и демонстрационные студенты

Схема — черновик до согласования с Кириллом. Таблицы: groups, users, sessions, subjects, lessons, grades, requests, notifications. Уведомления пока персональные, оценки хранят текстовый результат; updated_at заявки обновляет код при изменении.

После запуска PostgreSQL:

```sh
npm run db:migrate
npm run db:seed
```

Если демостуденты уже были созданы раньше и вход возвращает «Неверный логин или пароль», задайте `SEED_STUDENT_1_PASSWORD` и `SEED_STUDENT_2_PASSWORD` в `.env` и отдельно выполните `npm run db:reset-demo-passwords`. Эта команда обновляет пароли только двух демостудентов и отзывает их старые сессии; обычный `db:seed` пароли существующих аккаунтов не меняет.

Если поменяли `SEED_TEACHER_PASSWORD` для уже существующего `teacher@mukpid.ru`, выполните `npm run db:reset-demo-teacher-password`. Команда обновит только пароль преподавателя и отзовёт его старые сессии.

До seed задайте в .env SEED_STUDENT_1_PASSWORD и SEED_STUDENT_2_PASSWORD (минимум 12 символов). В текущем локальном .env уже созданы случайные пароли. Не отправляйте .env в репозиторий. Email: student@edu.mukpid.ru и student2@edu.mukpid.ru; группы ДЕМО-МО-101 и ДЕМО-ЭК-202. Все данные вымышленные. Пароли в базе — Argon2id. Повторный seed не создаёт студентов заново и не меняет их пароли, обновляет только данные демонстрационных групп. Seed запрещён при NODE_ENV=production.

После изменения schema.ts: npm run db:generate, просмотреть SQL и выполнить npm run db:migrate. Миграции коммитить вместе со схемой. Другие таблицы пока пусты; вход и доступ к собственному профилю реализованы.

## Проверка авторизации

`npm test` запускает интеграционные проверки на базе из .env: создаёт уникальные временные группы и студентов, затем удаляет их. Требуется работающий PostgreSQL с применёнными миграциями. Демоаккаунты не меняются. Контракт cookie, CSRF и форматы ответов описаны в docs/api.md.

## JWT и роли

После обновления выполните `npm run db:migrate` и `npm run db:seed`. Задайте JWT_SECRET (случайный секрет минимум 32 байта) и SEED_TEACHER_PASSWORD (минимум 12 символов) в .env; в текущем локальном окружении они уже созданы. Старые студенты сохраняют ID и пароли, вход теперь по email. Добавлен teacher@mukpid.ru с ролью teacher, без учебной группы. Seed повторно не меняет существующие пароли. Авторизация работает через JWT в HttpOnly-cookie и серверную сессию; детали в docs/api.md.
