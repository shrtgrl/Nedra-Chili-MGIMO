# Цифровой деканат — конкурсный прототип

Колясик — API, база, безопасность и деплой; Аслан — интерфейс; Кирилл — спецификация, контент и отчёт. Требования: [spec.md](spec.md). Фактические контракты: [docs/api.md](docs/api.md). Только вымышленные персональные данные.

## Запуск

Нужны Node.js 22+, npm, Docker с Compose (либо отдельный PostgreSQL).

```sh
cp .env.example .env
npm ci
npm ci --prefix apps/web
```

Задайте в `.env` случайный JWT_SECRET (минимум 32 байта), реквизиты БД и четыре SEED_*_PASSWORD (12+ символов). Не коммитьте `.env`.

```sh
npm run dev:all
```

Команда запускает PostgreSQL, применяет миграции, заполняет вымышленные данные и запускает API и интерфейс. Интерфейс — http://localhost:5173, API — http://127.0.0.1:3001/health. Ctrl+C останавливает процессы и контейнер БД, volume сохраняется. `npm run dev:stop` отдельно останавливает БД.

Для уже работающего PostgreSQL:

```sh
npm run db:migrate
npm run db:seed
npm run dev
# В другом терминале:
npm run dev --prefix apps/web
```

После обновления ветки обязательно применить миграции, включая 0006 и 0007. Не запускайте API новой версии со старой схемой.

## Neon

Настройки Neon находятся в `neon.ts`; локальная привязка проекта `.neon` и секреты `.env`/`.env.local` не сохраняются в Git. После `npm ci` CLI доступен как `node_modules/.bin/neon`. Для применения настроек используйте `node_modules/.bin/neon deploy --no-env-pull`. Адреса БД можно получить командой `node_modules/.bin/neon env pull --file .env.local -e DATABASE_URL -e DATABASE_URL_UNPOOLED`. Миграции используют прямой `DATABASE_URL_UNPOOLED`, если он задан; API использует `DATABASE_URL`. Для тестов нужен отдельный `TEST_DATABASE_URL`. Публичное приложение использует отдельную ветку Neon `amvera-demo`; не применяйте к ней локальные интеграционные тесты.

## Кабинеты

- Студент: серверные заявки/PDF, уведомления, своё расписание, оценки, обращения преподавателям, материалы группы.
- Преподаватель: своё расписание, ведомости назначенных групп, обращения/ответы, загрузка учебных файлов.
- Сотрудник: очередь заявок, проверка и черновик справки, выпуск/отказ/выдача, редактирование расписания и CSV.

Назначения дисциплин/групп управляются через БД; отдельного административного экрана пока нет. Seed добавляет назначения демопреподавателю, баллы, заявки, обращения, материалы и уведомления для двух демогрупп. Повторный запуск дополняет недостающие записи и сохраняет существующие пароли. Старые произвольные занятия без teacher_id не связываются с преподавателями по ФИО. Исторические текстовые оценки остаются в прежней grades; новые баллы хранятся в grade_entries.

Основные разделы читают API. При ошибке серверные данные не подменяются демонстрационными. Преподаватель публикует учебные дедлайны для своих групп, сотрудник — объявления для всех студентов или выбранной группы. Полноценный Web Push/почта, юридические документы, антивирус файлов, полноценные серии и атомарный CSV-импорт пока не реализованы. Часть старых констант макета остаётся для подписей и оформления.

Учебные дедлайны преподаватель публикует для назначенной ему группы в разделе «Дедлайны»; студент видит ближайшие сроки на главной. Для этого нужна миграция 0008 (`npm run db:migrate`). Сотрудник публикует объявления для всех или одной группы в разделе «Объявления»; миграция 0009 добавляет их хранение.

## Демоаккаунты

student@edu.mukpid.ru, student2@edu.mukpid.ru, teacher@mukpid.ru, staff@staff.mukpid.ru. Роль определяется сервером; домен email прав не даёт. Пароли — только из окружения, хеши Argon2id. Повторный seed сохраняет пароли. Сброс с отзывом сессий:

```sh
npm run db:reset-demo-passwords
npm run db:reset-demo-teacher-password
npm run db:reset-demo-staff-password
```

Seed и сброс запрещены в production.

## Проверки

```sh
npm run check
npm run build
npm run build --prefix apps/web
npm run test:unit
```

Для интеграционных тестов создайте **отдельную** PostgreSQL-базу и задайте TEST_DATABASE_URL. Тесты создают временные вымышленные записи и удаляют их. Миграции на тестовой базе можно применить из apps/api:

Для локальной PostgreSQL из `.env` используйте `npm run test:local`: команда создаёт отдельную базу `dean_integration_test`, применяет к ней миграции и запускает интеграционные тесты. Она проверяет, что адрес базы — localhost/127.0.0.1, и не меняет демонстрационную базу.

```sh
DATABASE_URL="$TEST_DATABASE_URL" ../../node_modules/.bin/drizzle-kit migrate
```

Из корня: `npm run test:integration`. Без TEST_DATABASE_URL команда завершится ошибкой с объяснением; проверки БД не считаются пройденными. `npm test` запускает оба набора. Workflow API integration поднимает отдельную PostgreSQL в CI.

## Публикация

Демо опубликовано на Amvera: https://mgimo-vibecode-hack-betlick.msk1.amvera.tech/. База находится в ветке Neon `amvera-demo`. API и собранный интерфейс работают в одном контейнере на порту 3001; `/api` обслуживает тот же origin. Для работы опубликованного сайта запускать Docker на своём компьютере не нужно.

`Dockerfile` собирает API и веб-клиент, `amvera.yaml` задаёт Docker toolchain и порт, `.dockerignore` исключает локальные секреты. В переменных Amvera на этапе «Запуск» заданы `DATABASE_URL` (ветка `amvera-demo`, секрет), `JWT_SECRET` (секрет) и `APP_ORIGIN` (точный HTTPS-адрес сайта без завершающего `/`). `NODE_ENV=production`, `HOST=0.0.0.0` и `PORT=3001` заданы в контейнере. Содержимое `.env` и `.env.neon-demo` не публикуется. Вместе с API в образ включены `apps/api/assets` для кириллического PDF.

Перед отправкой версии с новыми миграциями примените их к целевой ветке Neon, используя её строку подключения; только после этого обновляйте сервер. Из корня проекта для демоветки (после получения `.env.neon-demo` с `DATABASE_URL` и `DATABASE_URL_UNPOOLED`):

```sh
cd apps/api
env -u DATABASE_URL -u DATABASE_URL_UNPOOLED node --env-file=../../.env.neon-demo ../../node_modules/drizzle-kit/bin.cjs migrate
cd ../..
```

Для обновления контейнера закоммитьте изменения в `main` и отправьте её в `master` репозитория Amvera:

```sh
git -c http.version=HTTP/1.1 push amvera main:master
```

Amvera собирает и перезапускает приложение после push. При изменении переменных окружения перезапустите контейнер в панели Amvera. `/health` подтверждает работу процесса, а подключение к БД проверяйте входом и чтением данных в кабинетах. Обновление сайта не требует повторного seed; демоданные в Neon сохраняются отдельно от контейнера.
