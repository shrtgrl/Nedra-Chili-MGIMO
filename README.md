# Цифровой деканат — конкурсный прототип

Колясик — бэкенд; Аслан — интерфейс; Кирилл — продукт и отчёт.

## Локальный запуск

Нужны Node.js LTS, npm и Docker с Compose для базы.

```sh
cp .env.example .env
npm install
docker compose up -d db
npm run dev
```

Откройте http://127.0.0.1:3001/health — ожидается `{"status":"ok"}`.
Проверка типов: `npm run check`. Сборка: `npm run build`. Запуск сборки: `npm start`.
Сервер /health запускается без базы. Схема из восьми таблиц описана в apps/api/src/schema.ts, SQL-миграции — в apps/api/drizzle.
Значения .env.example предназначены только для локальной разработки. При изменении реквизитов обновите также DATABASE_URL.

## Следующий этап

Согласовать docs/api.md с Асланом и поля данных с Кириллом. Схема и два студента уже созданы локально. Вход, выход и GET /api/auth/me реализованы. Далее — API расписания, оценок, заявок и уведомлений.
Авторизация и профиль реализованы. Остальные бизнес-маршруты, интерфейс и публичный деплой пока не реализованы.

## Таблицы и демонстрационные студенты

Схема — черновик до согласования с Кириллом. Таблицы: groups, users, sessions, subjects, lessons, grades, requests, notifications. Уведомления пока персональные, оценки хранят текстовый результат; updated_at заявки обновляет код при изменении.

После запуска PostgreSQL:

```sh
npm run db:migrate
npm run db:seed
```

До seed задайте в .env SEED_STUDENT_1_PASSWORD и SEED_STUDENT_2_PASSWORD (минимум 12 символов). В текущем локальном .env уже созданы случайные пароли. Не отправляйте .env в репозиторий. Email: student@mukpid.example и student2@mukpid.example; группы ДЕМО-МО-101 и ДЕМО-ЭК-202. Все данные вымышленные. Пароли в базе — Argon2id. Повторный seed не создаёт студентов заново и не меняет их пароли, обновляет только данные демонстрационных групп. Seed запрещён при NODE_ENV=production.

После изменения schema.ts: npm run db:generate, просмотреть SQL и выполнить npm run db:migrate. Миграции коммитить вместе со схемой. Другие таблицы пока пусты; вход и доступ к собственному профилю реализованы.

## Проверка авторизации

`npm test` запускает интеграционные проверки на базе из .env: создаёт уникальные временные группы и студентов, затем удаляет их. Требуется работающий PostgreSQL с применёнными миграциями. Демоаккаунты не меняются. Контракт cookie, CSRF и форматы ответов описаны в docs/api.md.

## JWT и роли

После обновления выполните `npm run db:migrate` и `npm run db:seed`. Задайте JWT_SECRET (случайный секрет минимум 32 байта) и SEED_TEACHER_PASSWORD (минимум 12 символов) в .env; в текущем локальном окружении они уже созданы. Старые студенты сохраняют ID и пароли, вход теперь по email. Добавлен teacher@mukpid.example с ролью teacher, без учебной группы. Seed повторно не меняет существующие пароли. Авторизация работает через JWT в HttpOnly-cookie и серверную сессию; детали в docs/api.md. Макет использует локальные заглушки и пока не подключён.
